# Авторизация и доступ к отчётам

С 17 ноября 2026 сервер проверяет подписанные Bearer-сессии. Переданные
`current_user_id`, `X-User-Id` и `X-User-Role` не дают никаких прав. Пользователь,
его роль и связи врача с пациентами проверяются по базе при запросе.

Отчёт по `/report/123` доступен после входа владельцу или связанному врачу.
Для остальных существующий и несуществующий ID возвращают одинаковый отказ.
Служебные CRUD-маршруты и универсальный AI Hub доступны только администратору.

Кнопка «Поделиться защищённой ссылкой» выдаёт подписанный токен на один отчёт
сроком до семи дней. Токен передаётся в URL-фрагменте и заголовке
`X-Report-Token`, поэтому не попадает в URL серверных запросов. Получатель
такой ссылки может открыть отчёт без входа. Не передавайте ссылку посторонним.
Токен отчёта не подходит для входа и открытия других отчётов.

При анонимном анализе сервер возвращает такой же токен только в результате
создания отчёта. Перебор ID не позволяет получить его повторно.

Пароли: PBKDF2-SHA256, 600000 итераций, отдельная случайная соль.
При первом старте новая колонка `password_hash` добавляется штатным механизмом
обновления схемы. Старые пароли врачей переносятся из `phone` в хеши,
`phone` очищается. Пароли пользователей сохраняются, но войти нужно заново.
Коды из писем хранятся как HMAC, потребляются атомарно, попытки входа и отправки
писем ограничены счётчиками в БД. Логи не выводят коды и SQL-параметры.

API-ответы не кэшируются; service worker v3 очищает прежний офлайн-кэш и
больше не сохраняет API, авторизованные ответы и внешние фотографии.

## Выкатка и откат

1. Выполнить `bash deploy-backend.sh`: он создаёт `db.bak-<stamp>.sql.gz`
   с правами только root, копии кода и окружения, сохраняет настройки ИИ.
2. Выполнить `bash deploy-frontend.sh`, чтобы браузер отправлял новые сессии.
3. Проверить вход врача/пациента, историю, отказ без входа и защищённую ссылку.

После миграции старый код входа не умеет читать хеши. Для отката используйте
совместимую версию входа; восстановление всей базы из резервной копии — только
при необходимости, поскольку оно отменит изменения данных после копии.
Не восстанавливайте базу автоматически поверх новых отчётов.

Уже скачанные PDF, старые резервные копии и ранее известные публичные адреса
изображений S3 этим изменением не отзываются. Для закрытия ранее опубликованных
фото требуется отдельное изменение политики бакета и способа выдачи фотографий.

Тесты: `.venv/Scripts/python -m pytest backend/tests/test_access_control.py`.
Они используют только временную SQLite-базу и подменённые вызовы ИИ/почты.
